# 설계 문서 — 소스코드 교육 가이드 (`docs/소스코드_가이드.md`)

작성일: 2026-06-22
상태: 승인됨(브레인스토밍 합의 완료), 구현(문서 작성) 대기

## 1. 목적·배경
`video_player` 소스코드를 **교육 자료**로 설명하는 단일 가이드 문서를 만든다.
이 프로젝트를 예제 삼아 mpv 기반 플레이어의 구조·설계 패턴·검증 워크플로우를 가르치는 것이 목표다.
(코드 자체는 이미 구현되어 PR #1 로 올라가 있으며, 이 문서는 그 코드를 *설명*한다.)

## 2. 독자
- **Python 은 알지만 이 도메인은 처음인 사람.**
- 따라서 Python 문법(클래스/데코레이터/타입힌트 등)은 설명하지 않는다.
- 대신 도메인 개념(mpv/libmpv·DRM/KMS·헤드리스·VA-API·테스트 계층 등)과
  아키텍처·설계 의도("왜 이렇게 했는가")를 풀어서 설명한다.

## 3. 범위
- **포함**: 아키텍처 흐름, 핵심 모듈(`player`·`controller`·`cli`) 깊은 설명,
  도메인 개념 primer, 검증 워크플로우(계층 0~3·TDD), 설계 패턴 정리, 간단 실습.
- **핵심 위주**: 보조 모듈(`config`·`constants`·`errors`·`logging_setup`·`keyboard` 일부)은 요약.
- **제외(YAGNI)**: 모든 줄을 망라하는 라인-바이-라인 주해, API 레퍼런스 자동생성,
  Python 언어 기초 튜토리얼.

## 4. 형식 결정
- 파일: `docs/소스코드_가이드.md` (단일 파일, A안)
- 언어: 한국어 (프로젝트 문서 관례와 동일; 코드 식별자는 영어 그대로 인용)
- 다이어그램: **ASCII** (어디서나 렌더링, 도구 의존 없음) — 단방향 흐름·모듈 의존
- 서술 뼈대: **실행 흐름 따라가기** (`player video.mp4` 한 줄에서 출발)
- 교육 장치: 곳곳에 "왜 이렇게?" 콜아웃, 마지막에 "직접 해보기" 실습

## 5. 문서 구조 (목차)
1. **들어가며** — 대상 독자·목적·읽는 법, 프로그램이 하는 일 한 문단
2. **큰 그림(아키텍처)** — `입력원 → Controller → Player → mpv` 단방향 흐름
   ASCII 다이어그램 + 각 박스 한 줄 역할 + "왜 단방향·분리?" 콜아웃
3. **도메인 개념 미니 primer** — 2~4줄씩: 헤드리스, DRM/KMS·HDMI, mpv/libmpv·FFmpeg,
   python-mpv, VA-API 하드웨어 디코딩·SW 폴백, OSD, TTY 원시모드, 종료 코드
4. **실행 흐름 따라가기(본론)**
   - 4.1 진입: `cli.main` 인자/파일 검증 → 종료 코드 2
   - 4.2 설정: `Config` 의 mpv 옵션(보안·성능·출력)이 *왜* 이런지 (성능 노트 연결)
   - 4.3 **엔진: `Player` + libmpv** (깊게) — 초기화, 지연 import 이유, EOF/디코드오류 이벤트
   - 4.4 **입력→동작: `keyboard` → `Controller`** (깊게) — `parse_key` 순수함수,
     `Action` enum, pause 토글·볼륨 클램프, 플랫폼 경계 격리
   - 4.5 **재생 루프: `cli.play`** (깊게) — 스레드로 EOF 대기 + 키 입력,
     graceful 종료(q/Esc/EOF/SIGINT·SIGTERM), 종료 코드 매핑(0/2/3)
   - 보조 모듈은 요약, 곳곳에 "왜 이렇게?" 콜아웃
5. **검증 워크플로우** — 계층 0(정적)/1(단위·mock)/2(통합·실 mpv vo=null)/3(실기기),
   TDD 흐름, `conftest` 의 ffmpeg 픽스처·Windows libmpv 주입, "테스트가 곧 명세"
6. **설계 패턴 모아보기** — 단방향 의존, 의존성 주입, 플랫폼 경계 격리,
   지연 import, Protocol, 단일 책임 (4장에서 흩뿌린 것을 요약)
7. **직접 해보기** — 실습 과제: 새 키 바인딩 추가는 어디를? 새 입력원(IPC) 연결은? 테스트는 어디에?
8. **더 읽을거리** — `docs/SPEC.md`·`docs/OVERVIEW.md`·`docs/성능_자원_노트.md` 링크

## 6. 성공 기준
- 도메인이 처음인 Python 개발자가 이 문서만 읽고:
  - `player video.mp4` 실행 시 어떤 모듈이 어떤 순서로 동작하는지 설명할 수 있다.
  - 새 키 바인딩/입력원을 어디에 추가해야 하는지 짚을 수 있다.
  - 계층 0~3 검증이 각각 무엇을 보장하는지 구분할 수 있다.
- 코드 인용은 실제 소스와 일치해야 한다(파일·식별자명 정확).
- 분량은 "핵심 위주" — 핵심 3개 모듈은 깊게, 나머지는 요약 수준.

## 7. 비목표 / 주의
- 코드 동작을 바꾸지 않는다(문서만 추가).
- 코드와 문서가 어긋나지 않도록, 작성 시 실제 소스를 직접 인용·대조한다.
