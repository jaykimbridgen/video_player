# PM_NOTES — video_player

> **구현 대상 아님 / PM 인지용.** claude-cli는 이 문서를 구현에 반영하지 않는다.
> 사람(PM)이 민감 사항·추후 검토 항목을 인지하기 위한 노트.

---

## 1. 코덱 특허 라이선스
- 현재는 내부 파일럿 → FFmpeg/mpv(오픈소스)로 디코딩하므로 실무적 문제 없음.
- 단, **H.264, H.265(HEVC), AAC, AC-3/DTS** 등은 특허 풀(로열티 대상) 코덱.
  *디코딩이 기술적으로 된다*는 것과 *상업적으로 배포할 법적 권리가 있다*는 것은 별개.
- 로열티프리 대안: VP9, AV1, Opus.
- ▶ **배포·상업화 전환 전, 취급 코덱에 대한 코덱 라이선스·법률 검토를 받을 것.**
- (법률 자문이 아니라 인지용 사실 정리.)

## 2. libmpv 라이선스
- libmpv 클라이언트 API 자체는 **ISC**지만, **mpv 코어는 GPLv2+**.
- libmpv를 쓰는 애플리케이션이 GPL 영향을 받는지는 법적 회색지대.
- ▶ 상업 배포 전 검토 대상(1번과 함께).

## 3. 추후 보안 검토 (현재 구현 불필요)
- **샌드박싱**: 신뢰 못 할 콘텐츠를 다루게 되면 seccomp/AppArmor/firejail로 디코더 격리 고려.
- **서비스 하드닝**: systemd 서비스/키오스크 자동 실행 시 `NoNewPrivileges`·`ProtectSystem`·`PrivateTmp` 등 적용.
- **IPC/네트워크 표면**: 프론트 IPC가 붙으면 로컬 전용(UDS/localhost)으로 묶고 명령 검증, 네트워크 노출 금지.

## 4. 추후 성능·자원 컨틴전시 (현재 구현 불필요)
- 현재는 재생 전용 기기라 CPU 격리 불필요. 다른 프로세스가 추가되어 경합이 생기면
  HW 디코딩 보장 → 프레임 드롭 → 디코딩 스레드 제한 → `nice` → CPU 어피니티 → cgroups → 사전 트랜스코딩
  순으로 필요한 만큼 escalation.
- 상세(카드 표·인접 변수)는 `docs/성능_자원_노트.md` 참고.

## 5. 추후 기능 (이번 범위 밖)
- **블루투스 리모컨**: 별도 변환 daemon 없이, player가 `/dev/input/eventX`(evdev)를 직접 읽어
  액션에 매핑하는 방식 권장. (멀티미디어 키는 TTY로 안 들어올 수 있어 evdev 직접 읽기가 견고.)
- **프론트엔드 + IPC**: 프론트가 player를 자식 프로세스로 띄워 제어.
  - 전송: stdin/stdout+JSON(가장 단순) / UDS+JSON(견고) / localhost WebSocket(웹·원격).
  - 메시지 포맷은 mpv JSON IPC 설계(명령 배열·request_id·event)를 템플릿으로.
  - 양방향 필요(명령 + 상태 이벤트). **입력 소유권은 한 곳에만** — 프론트가 evdev를 소유하면 player는 IPC 명령만 수신.
- 자막, 재생목록/큐, 이어보기(상태 저장), 오디오 패스스루(돌비/DTS 비트스트림).
